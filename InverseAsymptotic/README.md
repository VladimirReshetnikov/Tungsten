# InverseAsymptotic — real-branch asymptotics of inverse functions

- Created (UTC): 2026-06-26T04:57:01Z
- Repository HEAD: 3915ec6ce0cb1e3f3fc06c73b6d7ebeebae20f43

A Wolfram Language package that computes the **asymptotic expansion of the real-valued
branch of an inverse function**, in the generalized power–logarithm scale the inverse
actually lives in — including the cases where every built-in (`InverseFunction`,
`Asymptotic`, `AsymptoticSolve`, `InverseSeries`) either returns unevaluated, returns
`Undefined`, or silently expands about the *wrong* (complex) branch.

It is the direct answer to
[“How to get an asymptotic of the real-valued branch of the inverse function”](https://mathematica.stackexchange.com/questions/236367)
on Mathematica StackExchange.

```wolfram
Get["src/InverseAsymptotic/InverseAsymptotic.wl"];

InverseAsymptotic[x + x^2 (1 + Log[x]), x, y, 3]
(*  y + (-1 - Log[y]) y^2 + (3 + 5 Log[y] + 2 Log[y]^2) y^3 + O(y^4)  *)

InverseAsymptotic[x + x^Sqrt[2], x, y, 4]
(*  y - y^Sqrt[2] + Sqrt[2] y^(2 Sqrt[2]-1) + (1/Sqrt[2] - 3) y^(3 Sqrt[2]-2)
        + O(y^(4 Sqrt[2]-3))                                                  *)
```

Both results are produced for the real branch through `x = 0`, in the exact scale the
asker wanted.

## The problem, and why the built-ins miss it

Take `f(x) = x + x^2 (1 + Log x)`, mapping `R+ -> R+`, and ask for the asymptotics of
`f^(-1)(y)` as `y -> 0+`. The honest answer is

```
f^(-1)(y) = y - y^2 (1 + Log y) + y^3 (3 + 5 Log y + 2 Log^2 y) + ...
```

— a series carrying **logarithms**. No ordinary power series can represent it, because
`f` is not analytic at `0` (its second derivative `5 + 2 Log x` blows up there). So:

- `InverseSeries[Series[f, …], y]` returns unevaluated — there is no Taylor reversion.
- `AsymptoticSolve[f == y, x, y -> 0]` returns unevaluated.
- `Series[InverseFunction[Function[x, f]][y], {y, 0, 2}]` *does* return a series — but
  one built around `E^(-1 + ProductLog[-1, -E])`, a **nonzero complex** number. That is
  not a bug. `InverseFunction` is contractually an *analytic* inverse; since `f` is not
  analytic at `0`, it instead solves `f(x) = 0`, whose relevant root
  `x0 = e^(-1 + W_{-1}(-e)) ≈ -0.1178 - 0.5332 i` is a nonzero complex point where `f`
  *is* analytic, and expands the inverse there. (One can check `f(x0) = 0` to ~79
  digits.) It answers a different question than “the real branch through `0`.”
- Wrapping `f` in `ConditionalExpression[…, Im[x] == 0]` only makes `Series`/`Asymptotic`
  return `Undefined`.

The second flagship example, `f(x) = x + x^Sqrt[2]`, fails differently: its inverse runs
on an **irrational, incommensurate exponent scale** — `1, Sqrt[2], 2 Sqrt[2]-1,
3 Sqrt[2]-2, …` (the additive monoid generated by `1` and `Sqrt[2]-1`) — which
`SeriesData` cannot even represent.

`InverseAsymptotic` handles both regimes by abandoning analytic reversion entirely and
reconstructing the real branch directly.

## Quick start

```wolfram
Get[FileNameJoin[{"src", "InverseAsymptotic", "InverseAsymptotic.wl"}]];

(* the two MSE examples *)
InverseAsymptotic[x + x^2 (1 + Log[x]), x, y, 3]
InverseAsymptotic[x + x^Sqrt[2], x, y, 4]

(* recovers classical inverses exactly *)
InverseAsymptotic[Exp[x] - 1, x, y, 5]    (* y - y^2/2 + y^3/3 - y^4/4 + y^5/5 = Log[1+y] *)
InverseAsymptotic[Sin[x],     x, y, 4]    (* ArcSin series *)
InverseAsymptotic[x - x^2,    x, y, 5]    (* y + y^2 + 2 y^3 + 5 y^4 + 14 y^5  (Catalan) *)
InverseAsymptotic[x Exp[x],   x, y, 6]    (* ProductLog (Lambert W) Maclaurin series *)

(* inversion at a nonzero point, and at infinity *)
InverseAsymptotic[Log[x], x -> 1,      y, 5]   (* 1 + y + y^2/2 + ... = Exp[y] *)
InverseAsymptotic[x + Log[x], x, y, 4, "At" -> Infinity]
(* y - Log[y] + Log[y]/y + (Log[y]^2/2 - Log[y])/y^2 + O(y^-3) *)
```

## What is supported

`InverseAsymptotic` works whenever the leading behaviour of `f` at the requested point is
a **pure power** `c x^p` (`c` a nonzero real, `p` any nonzero real — integer, rational,
or irrational), with the rest of `f` built from real powers, **integer powers of
logarithms**, and analytic compositions (`Exp`, `Sin`, `Cos`, `Sinh`, `Tan`, `ArcTan`,
… and `base^exp` with `exp` depending on the variable, e.g. `x^x`). Concretely it covers:

| category | example `f` | inverse scale |
|---|---|---|
| pure power, branch point | `x^2 + x^3` | `Sqrt[y] - y/2 + 5 y^(3/2)/8 - …` |
| analytic, `f'(0) != 0`    | `2x + x^2`, `Exp[x]-1`, `Sin[x]`, `Tan[x]` | ordinary Taylor |
| power + logarithm         | `x + x^2(1 + Log x)`, `x + x^2 Log x` | power · `Log`‑polynomial |
| irrational / incommensurate | `x + x^Sqrt[2]`, `x + x^(3/2)`, `x^Pi + x` | real exponent monoid |
| Lambert‑W with power head | `x Exp[x]` → `ProductLog[y]` | ordinary Taylor |
| at a nonzero point `a`    | `Log[x]` at `x -> 1`, `Cos[x]` at `x -> 0` | series in `(y - f(a))` |
| at infinity, image `-> ∞` | `x + Log x`, `x - Log x`, `x + Sqrt[x]` | descending powers + logs |
| one‑sided real branch     | `x^2` with `Direction -> "FromBelow"` → `-Sqrt[y]` | |

The **real** branch is obtained automatically: the iteration is seeded with the real
leading term `(z/c)^(1/p)` and every step is real, so it never drifts onto a complex
sheet the way `InverseFunction` can.

### Out of scope (reported, not guessed)

When the **leading term itself carries a logarithm** — `x Log x`, whose inverse is a
Lambert‑W / iterated‑logarithm object `y / ProductLog[y]` outside the `c z^p Log^k`
scale — the package emits `InverseAsymptotic::leadlog` and returns `$Failed` rather than
fabricating an answer. Likewise oscillatory / essential‑singularity inputs
(`Sin[1/x]`) with no leading monomial yield `InverseAsymptotic::nolead`. For a function
that is not locally injective at the point (`f'` vanishes to even order), the package
returns the single real branch matching the requested `Direction`; the other branch is
reached by flipping `Direction`.

## API

```
InverseAsymptotic[f, x, y, n]              (* expansion of f^(-1)(y), n power-levels  *)
InverseAsymptotic[f, x -> a, y, n]         (* same, with the expansion point a        *)
InverseAsymptoticData[f, x, y, n]          (* Association with full diagnostics        *)
```

- `f` — an expression in `x` (i.e. `f(x)`); `x`, `y` — symbols; `n` — number of distinct
  **power-levels** to keep (all logarithmic terms at a given power are kept together).
- The result is a plain sum of gauge monomials plus an inert `BigO[var, p]` remainder
  (displayed `O(var^p)`), in the spirit of `Asymptotic` (`SeriesData` cannot carry
  irrational or logarithmic exponents).

### Options

| option | default | meaning |
|---|---|---|
| `"At"` | `0` | the point `a` with `x -> a`; accepts a finite value or `±Infinity` (or use the `x -> a` rule form) |
| `Direction` | `"FromAbove"` | side of approach, `"FromAbove"`/`1` or `"FromBelow"`/`-1`; selects the one-sided real branch |
| `"ImagePoint"` | `Automatic` | the image value `b = f(a)`; inferred by default |
| `"Remainder"` | `True` | append the `BigO[…]` order term |
| `"Verify"` | `True` | run the numeric back-substitution check (emits `::verify` if weak) |
| `"VerificationTolerance"` | `10^-8` | residual floor for the verifier |

### Diagnostics (`InverseAsymptoticData`)

Returns an `Association` with: `"Expansion"`, `"Monomials"` (the raw `{coef, power,
logPower}` list for the inverse expressed in `x`), `"Leading"` (`{c, p}`), `"ImagePoint"`,
`"Side"`, `"RemainderExponent"`, `"InfiniteImage"`, `"Sigma"`, and — when `"Verify"` is on
— `"Verified"`, `"MaxResidual"`, `"MeasuredOrder"` (the empirically measured decay
exponent of the residual, which should match `RemainderExponent`).

## How it works

1. **Dominant balance.** Detect the leading monomial `c x^p` of `f` at the point (a limit
   computation; a leading logarithm is detected and refused here).
2. **Contractive fixed point.** Iterate
   `X <- ((z - f(X) + c X^p)/c)^(1/p)`
   from the real seed `X0 = (z/c)^(1/p)`. Each pass injects the next gauge term and the
   support grows but stays well-ordered, so the truncated series stabilizes.
3. **Transseries monomial arithmetic.** All expansion, multiplication, powering,
   `Log`, and analytic composition are done on a normal form of monomials
   `c · z^p · Log[z]^k` (`p` an exact real, `k` a non-negative integer), truncated by the
   **real value** of the `z`-exponent. This is what lets the engine carry irrational
   powers (`z^Sqrt[2]` via the binomial series in `z^(Sqrt[2]-1)`) and logarithms that
   `Series`/`Asymptotic` cannot. An equal-power logarithmic group is always kept or
   dropped as one unit, never split.
4. **Point / image normalization.** Finite or infinite expansion point, either approach
   direction, and finite or infinite image are reduced to the canonical `t -> 0+`,
   `z -> 0+` problem by local substitutions, with the sign bookkeeping carried through the
   monomial representation so the emitted expression is clean (no `Log[1/y]` artifacts).
5. **Numeric re-verification.** The back-substitution residual `f(X(y)) - y` is measured at
   a shrinking sequence of sample points; its empirical decay exponent must reach the
   claimed remainder order. (A fixed absolute tolerance would wrongly flag a low-order
   truncation, since an `O(y^4)` expansion legitimately has a sizable residual at moderate
   `y`.) This is the asymptotic analogue of the repository's PSLQ‑canary discipline.

This places the package in the classical theory of **transseries reversion over Hardy
fields**: the inverse of any logarithmico-exponential function is itself a transseries,
computable term by term by exactly this kind of generalized Newton/bootstrap iteration.
